# Artifact 7 — Visual identity

Bead: `kwaffee-x0i` (blocked by artifact 6). Source: grill memo `.scratch/kwafee/grilling/07-visual-identity.md` — every branch below is DECIDED there; this spec is the artifact's durable definition of done.

## Problem Statement (from the user's perspective)

When I look at KWA FEE — on a computer, on a phone, from across a party room at 3am — I need to know instantly whose game this is. The look has exactly two parents: How To Fish's squishy clay bodies and Gamble With Your Friends' candy arcade polish. Today I have 12 meshes, 11 materials, and a manifest, but nothing stops a future asset from drifting into "any other game": no one field says which parent a mesh traces to, colors live inline in one bpy script, nothing checks that two characters don't read as the same silhouette, and the idle wobble is not yet a language — some things bobble, some vibrate, nothing is consistent. I also cannot yet meet my own gate: artifact 7 demands 5 traceable characters, but only Barista and Customer exist. And I need the three missing cast members — the Shop Cat, Big Vinny, and a Dealer — to be real, finished, on-parent assets, not paper promises.

## Solution (user perspective)

Five living characters (Barista, Customer, Shop Cat, Big Vinny bust, Dealer base) plus the four machines as living props, every one machine-checked against the 8 rules with a named parent trace. One committed palette (`palette.json`) that Blender, the Unity validator, and the future UI all read — colors physically cannot drift. Two rendered contact sheets (full color + ink silhouette) with numeric pairwise shape-distance gates: no two characters read as the same silhouette, ever. One wobble language: every living thing and every machine carries rig hints, and exactly two runtime components (BobbleController, GooglyEyes) do all the idle motion — deterministic, seeded, zero-alloc, 60fps-safe. The neon sign, the van, the inspector, the landlord, street NPCs, and dealer tint variants are audited through the same conventions now and must pass the same validator when their artifacts author them. Artifact 7 locks the LOOK so every later artifact inherits it instead of re-deciding it.

## User Stories

1. As a player, I want the five beings in the shop (Barista, Customer, the Shop Cat, Big Vinny, a Dealer) to be instantly recognizable as the cast of KWA FEE, so that the game reads as one family even before any UI appears.
2. As a player, I want the four machines (Espresso, Grinder, Steam Wand, Ice Machine) to look like one designed set with their characters, so the shop feels coherent rather than assembled.
3. As a player, I want every humanoid to have a big rounded head and a one-piece clay body with the shirt painted on, so that I read "clay love letter" without thinking about it.
4. As a player, I want the Shop Cat to be a soft felt creature with googly eyes and a spring-swaying tail, so it reads as the beloved gremlin the spec promises before it knocks a single tray.
5. As a player, I want Big Vinny's bust to be unmistakably "20% head," so the deadpan narrator lands as comedy the moment he appears in the artifact-8 banner.
6. As a player, I want a Dealer whose body carries a tint-slot convention, so the three dealers (Big Sal, Rosie, Ma Paddy) become three color personalities later without new geometry.
7. As a player, I want everything that lives to have eyes — big glossy pucks that squash and follow — including a googly puck on each machine's soul, so rule 2 ("eyes carry the soul") holds everywhere, not just on the cast.
8. As a player, I want the idle world to be gently alive: humans bobble, the cat's tail springs, machines vibrate — from one consistent motion language, so the shop feels inhabited, never robotic or chaotic.
9. As a player, I want the palette to be pastry-warm base slammed against candy accents, so the shop is readable at a glance across the room, at 3am.
10. As a player, I want screens and meshes to share the same colors, so the UI never looks like it was painted over another game.
11. As the RATER, I want every model and prop to trace to a named parent rule with a written "why," so I can verify each LOOK decision instead of eyeballing vibes.
12. As the RATER, I want two reproducible evidence sheets — a full-lit color contact sheet and a flat-black ink-silhouette sheet — with printed pairwise IoU numbers, so the silhouette gate is a number I can re-run, not a claim.
13. As the RATER, I want the silhouette gate to fail loudly if any character pair reads as the same silhouette, so "two characters reading as same silhouette" is a blocker that cannot sneak past.
14. As a future asset author (artifact 5/6/8), I want the validator to reject my mesh at import if it drifts from the rules, the palette, or the material classes, so I cannot accidentally break the LOOK even with the best intentions.
15. As a future asset author, I want one canonical palette file to read, so I never inline a hex again and there is exactly one source of truth.
16. As a future asset author, I want a whitelist of material-class prefixes, so introducing a 4th material class is a deliberate, reviewed act rather than an accident.
17. As the artifact-11 UI builder, I want the CandyUI token contract (palette, corner radius, chunky borders, bounce curve, big icons) derived and documented by this artifact, so screens restyle in one pass without re-deriving the look.
18. As the gameplay engineer, I want the MeshManifest to be the single contract the Unity importer reads, so mesh additions never change gameplay code.
19. As the pipeline engineer, I want per-asset bpy scripts over one monolithic script, so parallel headless Blender runs are safe and each asset is reproducible in isolation.
20. As a performance owner, I want idle motion to be deterministic and zero-alloc, so the "world is alive" rule never threatens 60fps on a mid laptop.
21. As the game operations owner, I want the triangle total to stay under the 35,000 cap with a stated headroom, so the future van (artifact 5), dealer tints, and inspector can be authored without renegotiating the budget.
22. As the game ops owner, I want future mesh merges to report triangle deltas, so budget creep is visible at review, not discovered at import failure.
23. As the game ops owner, I want the new meshes grounded at y=0 (cat paws, Vinny bust base, dealer feet), so grounding stays a validator rule with no exceptions.
24. As the RATER, I want one material (felt) to be a real body material lived in by the Shop Cat, not trim on an apron, so rule 3's three materials are each honestly used.
25. As the RATER, I want the traceability table printed at build time and enforced at import time, so the check lives in machines, not prose that rots.

## Implementation Decisions

Every branch below is DECIDED in the grill memo; no options remain.

- **Roster (B1, B2).** Ships 12 existing meshes + Shop Cat + Big Vinny bust + ONE Dealer base — exactly 15 names: Cup, Barista, Customer, Counter, Floor, Wall, Tray, Sign, Espresso, Grinder, SteamWand, IceMachine, ShopCat, VinnyHead, Dealer. The gate's "5 characters" is met by the 5 beings; the 4 machines are roster-class "machine": they enter the pairwise silhouette test against each other AND against characters, but are not counted as characters. Unknown, duplicate, or missing required names fail import.
- **Audit shape (B3).** Extend the art manifest with per-mesh `look` fields: `{ parent: "clay"|"candy", rules: [1..8], trace: [{rule, why}], silhouetteId?, bobble?, eyes? }`. Two enforcement points: a build-time look-audit script (cheap, catches drift at authoring, prints the mesh×rule traceability table) and import-time `CoreSceneBuilder.Validate` (Unity refuses a non-compliant manifest). The narrative "why" lives in EVIDENCE.md and RATER-facing sheets; code holds only the check.
- **Palette lock (B4).** `palette.json` is the single source of truth — canonical hex values. The bpy-side palette module imports it; the inline palette dict in the art script is deleted (one convention, no second source). `CoreSceneBuilder.Validate` loads the json and rejects any manifest material whose color deviates > 0.01 per channel from its named palette key. Material naming encodes the key (`<class>_<paletteKey>`, e.g. `clay_cream` → `cream`), so validation is a name→hex map with no heuristics. Artifact 11's CandyUI consumes the same json so screens and meshes cannot drift.
- **Silhouette test (B5).** Extends the renderer into a silhouette-check module producing two composable sheets: (1) a full-lit color contact sheet for palette/rule eyeballing (RATER evidence) and (2) a flat-black ink-silhouette sheet — all materials forced to one ink material, ortho front 3/4 view, cropped to bbox. Numeric gate: normalized pairwise silhouette IoU < 0.60 among character pairs, < 0.50 among the 4 machine pairs, and characters-vs-machines at < 0.50 [DECIDED in synthesis: chars-vs-machines takes the stricter bar — a machine reading as a being is the worse failure, and machines' simpler geometry makes it achievable]. Thresholds tune-and-lock on the first honest run, then are fixed numbers; a false pass is a bug. Sheet PNGs land in the scratch dir as the artifact's evidence; numbers go to stdout.
- **Wobble language (B6).** Blender authors only rig hints — per-mesh `bobble: {pivot:[x,y,z], axis, class: "bobble"|"spring"|"vibrate", amp, rate}`, named `eyes` slots (position/scale per puck), and `squashPivot` for future physics deformation. One shared runtime `BobbleController` + `GooglyEyes` consume the hints procedurally: idle bobble (humans), spring sway (cat tail), vibrate (machines), googly-eye squash/cross/follow. Deterministic (seeded phase), zero-alloc delta sines on Transforms, 60fps-safe. "Wobble language consistent" = every living entity and every machine carries hints and ONLY these components move them; no hand-rolled idle anims anywhere. No bpy keyframe/animation export to GLB.
- **Re-authors (B7).** Targeted, not remade: (i) humanoid head proportions retuned to the bobblehead band — head diameter ≥ 0.35 × body height on all humanoids (current Barista ≈ 0.41 is inside; tune, don't rebuild); (ii) one googly-eye puck added to each machine (rule 2 — everything that lives includes the machine quartet's souls); (iii) all 12 existing meshes backfilled with `look`/`bobble`/`eyes` fields. NOT re-authored: Barista/Customer bodies (compliant: clay + eyes + felt apron), neon sign (audited: candy glossy + soda-blue + crooked; authored at its own artifact), the van (audited; artifact 5 authors within remaining triangle budget), dealer tint variants (Dealer BASE now; tints are color-spotlight swaps, not geometry, at artifact 5), inspector/landlord/street NPCs (audited; must pass the same validator when authored).
- **Screens (B8).** Artifact 7 locks the CandyUI token contract: palette from the canonical json, corner radius ≥ 8% of element min side, chunky border ≥ 3px at 1080p, one shared bounce tween curve, huge icons. The existing IMGUI HUD and awards text screen are checked against the tokens and flagged for restyle; the restyle itself is tracked work for artifact 11 (its named scope). Deriving the tokens is this artifact's job; building every screen is artifact 11's.
- **Pipeline shape (B9).** Split: a shared helper module (palette import + cube/uv/cyl/torus/join/eyes + look-field helpers), the existing 12-asset build script refactored onto it, three new per-asset build scripts (cat, Vinny, dealer — each writes its own output and own manifest fragment), and a manifest merge step that produces the single manifest the Unity importer consumes. Matches ADR-0005; parallel headless Blender runs are safe (separate processes, per-file ownership); the importer contract is unchanged; the merge step is the only shared write and must be file-level atomic.
- **Material-class guard (B10).** Material names MUST be `clay_*`, `plastic_*`, `felt_*`, or on the explicit specials whitelist (`coffee`, `ink`, `sign_red` — candy-class). Both the build-time audit and `Validate` reject unknown prefixes. One shared 3-material-class matrix is documented in the `look` schema: clay = matte bodies/furniture/env, plastic = glossy props/eyes/machines, felt = Shop Cat/aprons. Felt becomes a real body material (ShopCat), not apron trim.
- **Triangle budget (B11).** New assets: ShopCat ~3k, VinnyHead ~1.5k, Dealer ~2k, 4 eye pucks ~0.5k on top of 17,112 existing ≈ 24k total — under the 35,000 cap, validator-enforced. Remaining ≈ 11k headroom reserved for the van (artifact 5), dealer tint variants (cheap — tint swaps, not geometry), and the inspector (artifact 6). Future asset scripts MUST report triangle deltas at merge; a cap breach blocks import. This is the loud assumption future artifacts build against.
- **Grounding.** New meshes keep `bounds.min.y == 0` (cat paws, Vinny bust base, dealer feet) — the existing validator rule extends to the new names with no change.

## Testing Decisions

What makes a good test here: the LOOK must be enforced by machines a future asset author cannot skip, and evidenced by artifacts the RATER can re-run. Prose rots; numbers and hard failures do not.

- **Validator as the primary test.** `CoreSceneBuilder.Validate` is the import-time gate: exact 15-name roster (unknown/duplicate/missing fails), per-mesh look-shape (parent ∈ {clay, candy}, non-empty rules ⊆ 1..8, trace with ≥1 named rule for the 10 gate entries — 5 characters + Cup/Tray/Sign/Espresso/Grinder), material prefix whitelist, palette drift ≤ 0.01/channel, unique `silhouetteId` for the 5 characters, triangle cap ≤ 35,000. These are not separate tests; the validator is the gate and stays the contract.
- **Build-time audit.** The look-audit script at build time catches drift at authoring, prints the mesh×rule traceability table, and checks rule-3 prefixes + palette compliance. Two enforcement points for the same contract; the import gate is the final word.
- **Silhouette gate.** Automated render of the ink-silhouette sheet + pairwise normalized IoU computation; numbers to stdout, PNGs to scratch as RATER evidence. Pass conditions per B5. First run calibrates thresholds on real renders; after the first honest run they are locked and any later regression is a failure. Treat a false pass as a bug, not a gift.
- **Bobble contract test.** Every living entity + every machine carries `bobble` hints; a manifest scan asserts presence (this is where a missing hint is caught cheaply). Runtime motion is exercised by the existing Unity test lane: deterministic seeded phase and zero per-frame allocation are asserted programmatically; no idle anim outside BobbleController/GooglyEyes is introduced (code review + no new tween/animation calls on those objects).
- **Triangle discipline.** Validator-enforced cap plus merge-time delta reporting; the exact current total after this artifact is recorded in EVIDENCE.md as the baseline future artifacts build against.
- **Prior art.** Existing validator/import tool, existing `preview()` renderer (extended, not rewritten), existing manifest and triangle constraint, 21 EditMode tests green. New tests added only where a plausible regression would fail: look-field shape enforcement, palette drift, roster completeness, silhouette IoU — all through the validator path and the audit script, matching existing conventions.
- **Not tested by automation:** whether a design "could be from any other game" is a RATER judgment — the sheets, trace table, and IoU numbers are its evidence, not its replacement.
